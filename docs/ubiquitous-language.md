# ユビキタス言語

会話・ドキュメント・コードで同じ概念を同じ言葉で呼ぶための用語集。
ここにない言葉が必要になったら、コードに書く前にまずこの表に追加する。

## 中心となる概念

| 用語 | 意味 | 対応するコード |
|---|---|---|
| **Task** | やるべきこと1件。このアプリが扱う唯一の対象 | `Task` |
| **TaskId** | Task を一意に識別する値。Task の同一性はこれだけで決まる | `TaskId` |
| **TaskName** | Task が何をするものかを表す名前。空であってはならない | `TaskName` |
| **TaskList** | Task の集まり。単なる配列ではなく、集合としての振る舞いを持つ | `TaskList` |
| **TaskFilter** | TaskList から表示対象を選び出す条件 | `TaskFilter` |

なお **TaskListView** は上の並びには入らない。これはドメインの概念ではなく、
「タスク一覧の画面が表示に必要とするもの」という UI 側の関心事を表す型であり、
application 層に置かれている。

## Task の状態と操作

| 用語 | 意味 |
|---|---|
| **completed（完了）** | その Task が終わっている状態 |
| **active（未完了）** | その Task がまだ終わっていない状態 |
| **complete** | Task を完了にする操作 |
| **incomplete** | Task を未完了に戻す操作 |
| **rename** | Task の名前を別の名前に変える操作 |

## フィルタ

| 用語 | 意味 |
|---|---|
| **All** | すべての Task |
| **Active** | 未完了の Task だけ |
| **Completed** | 完了した Task だけ |

## remaining（残り）

**未完了の Task の件数**を指す。フィルタの選択状態とは無関係。

数え方は `TaskList.countActive()` が持つ。画面の都合ではなくドメインの知識であるため。

Completed フィルタを選んでいても「残り」の意味は変わらないため、
表示される件数も変わらない。

> **経緯**: T0-2 の特性テストで、`remaining` と表示しながら実際には
> 「現在のフィルタで表示中の件数」を数えていることが分かった。
> Completed フィルタでは「完了済みが1件」なのに「1 task remaining（残り1件）」と
> 表示されていた。言葉と実装のどちらを正とするかを検討し、
> **言葉を正として実装を直した**（T1-1）。

## アプリケーションの操作（ユースケース）

ユーザーが行える操作と、それを表すコード。

| 操作 | 意味 | 保存先を読み書きするか |
|---|---|---|
| **LoadTasks** | 保存されている Task 一覧を読み出す | する |
| **AddTask** | Task を追加する | する |
| **DeleteTask** | Task を取り除く | する |
| **RenameTask** | Task の名前を変える | する |
| **ToggleTaskCompletion** | Task の完了状態を切り替える | する |
| **FilterTasks** | 既に読み込まれた一覧を、指定のフィルタで絞り込む | しない |
| **CountRemainingTasks** | 既に読み込まれた一覧から remaining を数える | しない |
| **BuildTaskListView** | 画面が表示に必要とする一式（TaskListView）を組み立てる | しない |

### 読み書きする操作としない操作を分けている理由

FilterTasks と CountRemainingTasks は保存先を読まない。これらは保存されている
内容を変えない「見せ方」の操作であり、画面が既に持っている一覧に対する射影に
すぎないため。フィルタを切り替えるたびに保存先を読み直す必要はない。

書き込む操作は一貫性の単位（TaskRepository と TaskList）を必ず通し、
読み出す操作は画面の都合に合わせる、という分け方になっている。

なお `taskFilterNames()` は関数であってユースケースではない。状態も入力も
副作用もなく、ドメインが持つ取り決め（選べるフィルタとその並び順）を
presentation 層から見えるようにしているだけのため。

## 使わない言葉

| 使わない | 使う | 理由 |
|---|---|---|
| **Todo** | Task | 同じものを2つの名前で呼んでいた。`Todo.tsx` が `task` を受け取る状態だった |
| **edit** | rename | Task に対して行えるのは名前の変更だけであり、edit は何をするのか曖昧 |
| **list**（絞り込みの意味で） | filter | 一覧を読み出すのは LoadTasks。ListTasks は絞り込んでいるだけで、名前と実態がずれていた |

## 既知のギャップ

ユビキタス言語をまだ適用しきれていない箇所。意図的に残している。

| 箇所 | 現状 | 扱い |
|---|---|---|
| CSS クラス名 | `todoapp` / `todo-list` / `todo-label` / `todo-text` | 見た目に直結するため T1-1 では触らない |
| UI のボタンラベル | `Edit` | ユーザーに見える文言。変更はユーザーへの影響を伴うため別途判断する |
| アプリ名 | `TodoMatic` | 製品名であり、ドメインの用語ではない |
