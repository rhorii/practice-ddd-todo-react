# ユビキタス言語

会話・ドキュメント・コードで同じ概念を同じ言葉で呼ぶための用語集。
ここにない言葉が必要になったら、コードに書く前にまずこの表に追加する。

## 中心となる概念

| 用語 | 意味 | 対応するコード |
|---|---|---|
| **Task** | やるべきこと1件。このアプリが扱う唯一の対象 | `Task` |
| **TaskId** | Task を一意に識別する値。Task の同一性はこれだけで決まる | `TaskId` |
| **TaskName** | Task が何をするものかを表す名前。空であってはならない | `TaskName` |
| **TaskList** | Task の集まり。単なる配列ではなく、集合としての振る舞いを持つ | `TaskList` |
| **TaskFilter** | TaskList から表示対象を選び出す条件 | `TaskFilter`（T1-6） |

## Task の状態と操作

| 用語 | 意味 |
|---|---|
| **completed（完了）** | その Task が終わっている状態 |
| **active（未完了）** | その Task がまだ終わっていない状態 |
| **complete** | Task を完了にする操作 |
| **incomplete** | Task を未完了に戻す操作 |
| **rename** | Task の名前を別の名前に変える操作 |

## フィルタ

| 用語 | 意味 |
|---|---|
| **All** | すべての Task |
| **Active** | 未完了の Task だけ |
| **Completed** | 完了した Task だけ |

## remaining（残り）

**未完了の Task の件数**を指す。フィルタの選択状態とは無関係。

数え方は `TaskList.countActive()` が持つ。画面の都合ではなくドメインの知識であるため。

Completed フィルタを選んでいても「残り」の意味は変わらないため、
表示される件数も変わらない。

> **経緯**: T0-2 の特性テストで、`remaining` と表示しながら実際には
> 「現在のフィルタで表示中の件数」を数えていることが分かった。
> Completed フィルタでは「完了済みが1件」なのに「1 task remaining（残り1件）」と
> 表示されていた。言葉と実装のどちらを正とするかを検討し、
> **言葉を正として実装を直した**（T1-1）。

## 使わない言葉

| 使わない | 使う | 理由 |
|---|---|---|
| **Todo** | Task | 同じものを2つの名前で呼んでいた。`Todo.tsx` が `task` を受け取る状態だった |
| **edit** | rename | Task に対して行えるのは名前の変更だけであり、edit は何をするのか曖昧 |

## 既知のギャップ

ユビキタス言語をまだ適用しきれていない箇所。意図的に残している。

| 箇所 | 現状 | 扱い |
|---|---|---|
| CSS クラス名 | `todoapp` / `todo-list` / `todo-label` / `todo-text` | 見た目に直結するため T1-1 では触らない |
| UI のボタンラベル | `Edit` | ユーザーに見える文言。変更はユーザーへの影響を伴うため別途判断する |
| アプリ名 | `TodoMatic` | 製品名であり、ドメインの用語ではない |
